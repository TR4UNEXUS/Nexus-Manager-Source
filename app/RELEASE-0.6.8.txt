USB Loader 0.6.8 - USB Mods
2026-09-30

APP-ONLY UPDATE. Keep the working Nexus USB Mods M2 firmware and the working
0.6.7 USB Loader HOME launcher. No game, HOME launcher or forwarder reinstall
is needed. The HOME launcher loads switch/usbloader/USBLoader.nro from SD.
This release has passed host tests and a Switch build, not an on-console test
of the new importer. The existing M2 firmware route was user-confirmed working.

Use
---
1. Put trusted game mod files on USB:
   atmosphere/contents/<16-digit application title ID>/romfs/...
   atmosphere/contents/<title ID>/exefs/...                 (optional)
   atmosphere/exefs_patches/<patch group>/<build ID>.ips    (optional)
2. Close games and installers. Open USB Loader, then USB Mods (sixth tile).
3. It scans USB:/atmosphere. Y lets you browse to another Atmosphere folder;
   enter the folder containing contents/exefs_patches, then X: Use folder.
4. Select a game with A. Review RomFS, or explicitly include ExeFS if wanted.
   IPS groups appear separately and require their own review/confirmation.
5. Apply. Reboot before launching the game with USB connected.
6. After adding/removing/renaming RomFS files, scan and refresh that title.
   It is an explicit action, not a background watcher or a live game reload.

What is written
---------------
RomFS payload remains on USB. SD gets a small usb_romfs.idx in the game's
atmosphere/contents folder. The app generates exactly the same index format
as the working M2 PC registrar. The existing GTA 105-file, 52,508,088,424-byte
index was regenerated byte-for-byte in the host comparison, without reading
the game payload or writing either drive. Existing M1 ownership journals
are recognised and migrated on the next confirmed refresh.

Small, selected ExeFS files and IPS patches are cached on real SD. ExeFS:
main.npdm, main, rtld, sdk, subsdk0-f, and empty .stub variants. IPS/IPS32
records and unchanged hexadecimal build-ID names are validated. IPS matching
is global by build ID, NOT proof of which game it belongs to. Only import
trusted GAME patches for the correct executable version; never system patches.

New RomFS registrations create a 16-byte .nexus-mod-id on USB. It is staged,
flushed, verified and published through a non-replacing rename. Do not remove
or copy another game's identity marker over it. A failed staging operation
may leave a tiny .nexus-marker-*.tmp at the USB root; no game data is deleted.

Safety and recovery
-------------------
Unmanaged/conflicting SD files are refused, not overwritten. Existing physical
SD romfs folders, romfs.bin and exefs.nsp for that title must be resolved by
the user first. An identical existing file may be borrowed, never claimed as
owned. Refresh only replaces prior owned files if their old SHA-256 still
matches. Cached executable files absent from the new selection are retained;
this feature is not a general mod uninstaller or automatic stale-file purge.

All staged SD data is verified before activation. Old managed files are moved
to switch/usbloader/mod-backups/<transaction>/, with a manifest. The activation
index is published after patches, then the ownership journal. A pending record
blocks further registrations if interrupted. L: Recover in USB Mods rolls back
only matching pending SD changes, including a partial first registration.
Recovery can itself be resumed after interruption. Locally changed files or
backups are refused for manual investigation. Keep backup folders for rollback;
they are never automatically pruned. Completed updates are not rolled back by L.

Limits
------
Requires the Nexus USB Mods M2 companion, a writable USB drive, and real SD.
Not a generic import of all Atmosphere files. Boot configs, KIPs, sysmodule
folders, cheats, flags and romfs.bin/exefs.nsp archives are not imported.
Application-title range only. Per title: 1536 files, 2048 directories, depth 24,
1 MiB index, bounded UTF-8 paths; 32 MiB per ExeFS file, 4 MiB per IPS file,
64 MiB selected patch data. Oversized/unsupported inputs stop before activation.
Adding this feature does not guarantee every mod/game/homebrew is compatible.

The USB owner is shared; the importer never acquires raw usb:hs, resets a device
or installs firmware. A media-generation change stops work. Operations run off
the UI thread with existing progress/cancellation safeguards. Physical failure
or a kernel/driver deadlock cannot be made safe by app-level recovery alone.

Install / rollback
------------------
Close the app and connect the physical SD to your PC. Apply-App.ps1 -SdRoot D:\
checks the M2 package3 and existing app, backs up the NRO, stages and verifies
the new app, then replaces only switch/usbloader/USBLoader.nro. Alternatively,
back up that file and copy this ZIP's switch folder to SD. Do not put it on USB.

Restore USBLoader.nro from switch/usbloader/app-backups/<timestamp>/ to roll
back the app. Firmware/HOC/boot config and existing game registrations are not
changed by installing the app. Rolling back the NRO does not undo mods that
you subsequently register; keep their separate SD backups as well.

Build / verification
--------------------
Source is in the companion source ZIP with licenses and pinned dependencies.
build-nexus.ps1 uses two low-priority workers and a free-RAM guard.
New portable-core tests: canonical index, M1 journal migration, no-op refresh,
faults at every transaction mutation and during recovery, ownership conflicts,
malformed paths/markers/patches, media changes and system-file exclusion.
Existing forwarder/startup/worker tests also passed. Forwarder sources are
unchanged from 0.6.7; all allocated ELF runtime sections match except the
rebuild's GNU build-ID note. No new NSP or firmware is needed for this feature.
App logs say APP-0.6.8; unchanged embedded forwarder logs still say HBL-0.6.7.
